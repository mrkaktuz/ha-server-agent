# HA Server Agent

[English](README.md) · **Українська**

Невеликий агент для серверів на Ubuntu: дає **Home Assistant** бачити, що працює на сервері, і керувати цим —
процеси pm2, сервіси systemd, nginx, SSL-сертифікати, резервні копії Duplicati, сесії tmux, контейнери Docker,
fail2ban, оновлення пакетів. Без SSH: в агента власний HTTPS API, де кожен запит і кожна відповідь підписані
(Ed25519). Агент оновлюється сам із GitHub — одним натиском у Home Assistant.

```
Home Assistant ──https──▶ nginx (піддомен агента) ──▶ агент на 127.0.0.1:8787 (користувач без прав)
  інтеграція «HA Server Agent»                             │ sudo: лише «collect» / «action»
  (підписує запити, перевіряє підписи відповідей)          ▼
                                                  помічник root ── policy.yaml (що дозволено)
```

## Що з'явиться в Home Assistant

- **Сенсори для кожного сервера:** проблеми (кількість + повний стан для дашбордів), оновлення пакетів,
  скільки процесів pm2 працює, днів до кінця найближчого сертифіката, остання копія Duplicati, агент на зв'язку,
  потрібне перезавантаження, помилка в конфігу nginx.
- **Оновлення** «Агент» — нові версії агента з'являються в *Налаштування → Оновлення*, ставляться одним натиском.
- **Ремонти** — якщо агенту потрібен пароль (напр. вебінтерфейсу Duplicati), Home Assistant підкаже, куди його вписати.
- **Дія** `ha_server_agent.action` — перезапустити / зупинити / запустити процес pm2, сервіс чи контейнер,
  `nginx -t` + reload, запустити копію Duplicati зараз.

## Що потрібно

- Ubuntu 22.04 або 24.04 (права root для встановлення).
- (Під)домен, що вказує на сервер, напр. `agent.example.com` — для серверів, до яких Home Assistant ходить через інтернет.
- Home Assistant 2024.12 або новіший.

## Швидкий старт

**1. На сервері** — клонувати й встановити (один із рядків):

```bash
sudo git clone https://github.com/mrkaktuz/ha-server-agent /opt/ha-server-agent

# сервер, до якого HA ходить через інтернет (у --allow-ip — публічна IP вашого Home Assistant)
sudo /opt/ha-server-agent/install.sh --domain agent.example.com --allow-ip 203.0.113.7
# сервер, на якому працює сам Home Assistant
sudo /opt/ha-server-agent/install.sh --local
```

Наприкінці встановлювач показує **режим**, який вибрав, і **код підключення** (`HSA1:…`).

**2. У Home Assistant** — скопіювати `homeassistant/custom_components/ha_server_agent` з цього репозиторію в
`/config/custom_components/` і перезапустити Home Assistant (один раз).

**3.** *Налаштування → Пристрої та служби → Додати інтеграцію → **HA Server Agent*** → назва сервера + код
підключення. Усе: Home Assistant сам сполучиться з агентом. Код спрацьовує один раз і діє 24 години;
новий — `sudo ha-server-agent pair`.

## Режими мережі (вибираються автоматично)

| Режим | Коли | Як підключається Home Assistant |
| --- | --- | --- |
| **nginx** | на сервері працює nginx | Встановлювач додає nginx сайт для `--domain` (HTTPS, порт 443), що передає `/v1/` агенту на `127.0.0.1:8787` — порт агента ззовні закритий. Сертифікат: наявний, що покриває домен (напр. wildcard), інакше — новий від Let's Encrypt (перевірка через той самий nginx, оновлюється сам). Працює за Cloudflare як із проксі, так і без нього. |
| **власний HTTPS** | nginx немає (або `--no-nginx`) | Агент слухає порт **2053** зі своїм сертифікатом; Home Assistant закріплює його відбиток. Якщо увімкнений `ufw` — порт відкривається лише для `--allow-ip`. Cloudflare: лише DNS (сіра хмарка). |
| **локальний** | `--local` | `http://127.0.0.1:8787`, лише для Home Assistant на тій самій машині. |

Інші сайти nginx не зачіпаються.

## Що робить встановлювач

- Ставить `python3-cryptography`, `python3-yaml`, `git` (якщо немає), створює системного користувача `ha-agent`.
- **Сам знаходить**, що є на сервері: pm2 (усіх користувачів, з nvm теж), nginx і його сайти, сертифікати, Duplicati
  (сервіс чи контейнер, його порт), сесії tmux, Docker, fail2ban, власні сервіси systemd — і пише
  `/etc/ha-server-agent/policy.yaml` (що агент може показувати й робити; правити можна будь-коли).
- Налаштовує мережу, сервіс systemd, правило sudo лише для помічника, робить самоперевірку.

Повторний запуск `install.sh` оновлює код і зберігає ключі, підключених клієнтів, сертифікати й політику.
Видалення: `sudo /opt/ha-server-agent/install.sh --uninstall` (`--purge` — разом із налаштуваннями).

## Самооновлення

Раз на 3 години агент робить `git fetch` свого клону й порівнює з GitHub. Якщо є новий коміт — у Home Assistant
з'являється оновлення «Агент». *Встановити* → агент (в окремому unit systemd) робить `git reset --hard origin/main`
і `install.sh --update`, потім перезапускається з новим кодом. Журнал: `/var/log/ha-server-agent/update.log`.
Вручну: `sudo ha-server-agent update`. Вимкнути: `agent: {allow_update: false}` у `policy.yaml`.

## Безпека

| Рівень | Що робить |
| --- | --- |
| Мережа | Агент слухає `127.0.0.1` за nginx (або HTTPS зі своїм закріпленим сертифікатом); `allow_ips` (+ ufw) |
| Підпис запиту | Кожен запит підписаний приватним ключем Home Assistant (Ed25519): метод, шлях, час, одноразовий nonce, хеш тіла. Агент знає лише **публічний** ключ |
| Повтори | Час ±30 с, кожен nonce приймається один раз |
| Підпис відповіді | Агент підписує кожну відповідь своїм ключем, прив'язуючи до nonce запиту — Home Assistant знає, що говорить саме з цим сервером |
| Сполучення | Одноразовий секрет із коду підключення (HMAC), діє 24 год, після використання знищується |
| Перебір | 10 невдач → IP заблоковано на 15 хв; ліміт 120 запитів/хв; однакова відповідь `401` на будь-яку помилку автентифікації |
| Права | Мережевий процес — `ha-agent` без оболонки. Дії root — лише через помічника з двома командами (sudoers); помічник робить тільки дозволене в `policy.yaml`, фіксованим argv без оболонки, і звіряє ціль із поточним станом |
| Захищені сервіси | `ssh`, `sshd`, сам агент, `journald`, `dbus` зупинити неможливо |
| Оновлення | Лише з git-репозиторію; Home Assistant може запустити оновлення, але не передати код |
| Журнал | Кожна дія й сполучення → `/var/log/ha-server-agent/audit.log` |

Агент навмисно **не вміє** виконувати довільні команди, читати файли чи змінювати конфіги.

## Секрети

Якщо модулю потрібен пароль (зараз — захищений паролем вебінтерфейс Duplicati), агент це помічає, а Home Assistant
показує ремонт: додати `duplicati_password: "…"` у `/etc/ha-server-agent/secrets.yaml` (читає лише root).
Перезапуск не потрібен.

## Політика (`/etc/ha-server-agent/policy.yaml`)

| Модуль | Показує | Дії (типово) |
| --- | --- | --- |
| `system` | ОС, ядро, час роботи, навантаження, оновлення (усього / безпеки), потреба в перезавантаженні, збійні сервіси | — |
| `systemd` | Сервіси зі списку `units` | для кожного свій: `start`, `stop`, `restart`, `reload` |
| `pm2` | Процеси користувачів з `instances`: стан, CPU, пам'ять, перезапуски, час роботи | `start`, `stop`, `restart`, `reload` (+ `pm2 save`) |
| `nginx` | Версія, стан, `nginx -t`, сайти й домени | `test`, `reload`, `restart` — лише після вдалого `nginx -t` |
| `certs` | Сертифікати з конфігів nginx і Let's Encrypt: домен, видавець, днів до кінця | — |
| `duplicati` | Завдання (API Duplicati 2.1+): остання вдала копія, помилки, розмір | `run` |
| `tmux` | Сесії користувачів з `users`: вікна, команди, чи підключено | `kill` лише з `allow_kill: true` |
| `docker` | Контейнери | `start`, `stop`, `restart` (`containers: []` — будь-які, інакше лише перелічені) |
| `fail2ban` | Jail-и: заблоковано зараз / усього | — |
| `processes` | Топ-5 процесів за CPU і пам'яттю | — |
| `agent` | Версія, коміт, новіший коміт на GitHub | `update`, `check` |

## Команди на сервері

```
sudo ha-server-agent pair                новий код підключення
sudo ha-server-agent clients             хто підключений;  remove-client NAME — відключити
sudo ha-server-agent allow-ip IP ...     дозволені адреси клієнтів
sudo ha-server-agent detect              що знайдено;  --write --force — перезаписати policy.yaml
sudo ha-server-agent test                самоперевірка
sudo ha-server-agent update              оновити з GitHub
sudo ha-server-agent status
journalctl -u ha-server-agent            журнал сервісу
```

## Якщо щось не так

- **«Агент не прийняв код»** — код уже використано або він застарів (`sudo ha-server-agent pair`),
  або IP Home Assistant немає в `allow_ips` (`sudo ha-server-agent allow-ip <IP>`).
- **«Немає зв'язку»** — перевір DNS домену та порти 443 (режим nginx) чи 2053 (власний HTTPS) у фаєрволі провайдера.
- **Let's Encrypt не вдався** — домен має вказувати на сервер, а порт 80 має бути доступний; тоді агент ставить
  власний сертифікат (Home Assistant його закріплює) — працює й так. Подробиці: `/tmp/ha-server-agent-certbot.log`.
- Журнали: `journalctl -u ha-server-agent`, `/var/log/ha-server-agent/audit.log`, `/var/log/ha-server-agent/update.log`.

## Перевірка без сервера

`test/container-setup.sh` — Ubuntu 24.04 у Docker з nginx, tmux і pm2; ставить агента в режимі nginx і друкує код
підключення. `test/client.py` — підписані запити ззовні: дії, відмови політики, чужий підпис, підмінене тіло,
застарілий час, повтор nonce.
